# 포트원 이용권 결제 설정

1개월 2,990원, 1년 29,900원 이용권을 포트원 V2 일반 카드 결제로 한 번 구매한다. 카드 등록, 빌링키, 정기 청구는 사용하지 않는다.

## 계약 후 설정 순서

계약 전에도 포트원 콘솔의 개발 연동 테스트에서 테스트 채널을 추가할 수 있다. 포트원 공식 안내에 따라 테스트 채널과 테스트 키를 발급한 뒤 아래 연결 설정을 적용하면 SDK와 서버 검증을 테스트할 수 있다.

현재 웹사이트에는 준비 중 안내만 표시하며 결제 미리보기는 제공하지 않는다. `PAYMENTS_ENABLED`는 기본적으로 꺼져 있다. 키를 모두 설정해도 신규 결제와 결제 재개는 차단한다. 기존 결제의 결과 확인과 웹훅 처리는 키가 설정되어 있으면 유지한다.

1. 포트원 V2 상점을 만들고 PG 계약을 완료한다. 토스페이먼츠는 신모듈의 일반 카드 결제 채널을 사용한다. 다른 PG는 추가 필수 구매자 정보가 있는지 해당 채널에서 확인한다.
2. Supabase SQL Editor에서 기존 001부터 006까지 적용한 다음 `supabase/migrations/202611080007_payment_passes.sql`을 실행한다. 기록과 기존 관리자 이용권은 보존한다.
3. 아래 환경변수를 Vercel에 설정하고 재배포한다. 로컬에서는 `.env`를 사용한다. 테스트 키와 실결제 키를 섞지 않는다.
4. 포트원 웹훅 URL을 `https://서비스도메인/api/payments/webhook`으로 지정한다. 버전은 `2024-04-25`, 본문 형식은 `application/json`이다. 같은 환경의 웹훅 시크릿을 발급한다.
5. 테스트 채널에서 PC와 휴대폰 결제를 검증한 뒤 실결제 채널로 바꾸고 다시 배포한다.

| 환경변수 | 설정할 값 |
| --- | --- |
| `PAYMENTS_ENABLED` | 현재 `0` 유지. 결제 오픈을 결정한 뒤에만 `1`로 설정 |
| `PORTONE_STORE_ID` | V2 상점 ID |
| `PORTONE_CHANNEL_KEY` | 일반 카드 결제 채널 키 |
| `PORTONE_API_SECRET` | 서버 전용 V2 API Secret |
| `PORTONE_WEBHOOK_SECRET` | 서버 전용 웹훅 시크릿 |
| `PAYMENT_ORIGIN` | 서비스 주소. 예: `https://claude-design-green.vercel.app` |
| `SUPABASE_URL` | 기존 Supabase 프로젝트 URL |
| `SUPABASE_SECRET_KEY` | 서버 전용 Supabase secret key. 기존 `SUPABASE_SERVICE_ROLE_KEY`도 지원 |

설정이 하나라도 빠지면 결제를 진행하지 않고 준비 중 안내를 표시한다. 시크릿을 공개 환경변수나 브라우저 파일에 넣지 않는다. 로컬 복귀는 `PAYMENT_ORIGIN=http://localhost:3000`으로 테스트한다. 웹훅 수신에는 외부에서 접근 가능한 배포 주소가 필요하다.

## 구현 내용

- `POST /api/payments/prepare`: 인증 및 요청 출처 확인 후 서버 가격으로 주문 생성. 같은 계정의 동일 이용권 대기 주문은 30분간 재사용.
- 공식 브라우저 SDK `requestPayment`: 서버 주문으로 일반 카드 결제창 열기. 결제를 누를 때 SDK 번들을 불러옴.
- `POST /api/payments/confirm`: 주문 소유자 확인 후 공식 서버 SDK로 결제 조회. 주문 번호, 상점, 채널, 구매자 ID, 금액, 원화 통화 및 결제 상태 검증.
- `POST /api/payments/webhook`: 원문 서명 검증 후 포트원 API에서 최신 상태 조회. 고객이 창을 닫아도 권한 반영.
- `POST /api/payments/resume`: 같은 사용자 소유의 기존 주문으로 결제 재개.

모바일 복귀와 새로고침 후에도 계정별로 저장한 주문 번호로 결과를 확인한다. SDK 응답이나 복귀 URL 자체로 권한을 부여하지 않는다. 중복 클릭을 막고, 확인 요청 실패 시 재확인과 같은 주문으로 재결제하는 버튼을 제공한다.

주문 테이블은 일반 사용자의 직접 읽기와 쓰기를 차단한다. 검증 서버만 서비스 키로 결제를 반영한다. 결제 이용권과 관리자 이용권은 별도로 보관한다. 서버의 프리미엄 AI 권한 검사에서 두 이용권을 확인한다.

중복 확인과 웹훅 재전송은 이용 기간을 늘리지 않는다. 서로 다른 이용권을 추가 구매하면 기존 기간 뒤에 이어 붙인다. 한국 시간의 달력 기준으로 1개월 또는 1년을 더한다.

## 환불 운영

전액 취소는 포트원 콘솔에서 수행한다. 웹훅이 취소된 결제를 제외하고 이용 기간을 다시 계산하며 다른 결제와 관리자 이용권은 보존한다. 늦게 도착한 성공 알림으로 취소된 결제를 복원하지 않는다.

부분 취소는 상태를 별도로 기록하고 기존 이용권을 유지한다. 부분 환불에 따른 기간 조정 정책은 아직 정하지 않았으므로 운영자가 확인해야 한다. 초기에는 이용권 환불을 전액 취소로 처리하는 것을 권장한다. 고객이 직접 환불하는 화면은 제공하지 않는다.

## 실제 결제 검증

1. 테스트 채널에서 이용권을 구매하고 프로필과 프리미엄 AI 기능을 확인한다.
2. PC와 휴대폰에서 결제 후 정상 복귀하는지 확인한다.
3. 결제 직후 창을 닫고 웹훅만으로 권한이 반영되는지 확인한다.
4. 확인 중 연결을 끊고 결과를 재확인한다. 새 결제가 생성되지 않아야 한다.
5. 웹훅을 재전송해 이용 종료 시각이 늘어나지 않는지 확인한다.
6. 콘솔에서 전액 취소하고 해당 이용권이 제거되는지 확인한다.
7. 실제 판매자 정보, 이용약관과 환불 정책을 확정하고 PG 심사를 완료한다.

자동 테스트는 SDK 요청과 서버 검증, 실제 웹훅 서명, PostgreSQL 권한 및 중복 처리를 검증한다. 실제 결제창, 카드 승인, 배포 환경의 웹훅 수신은 포트원 계정과 테스트 채널 키가 있어야 검증할 수 있다. 계약 외에도 키 설정, SQL 적용, 재배포와 실제 결제 검증이 필요하다.
